Linux Suspicious Activity and SSH Security

A defensive lab for identifying unexpected accounts, processes, network listeners, and SSH access configuration.

Aim

To identify suspicious users, processes, network connections, and SSH configuration on a Linux system.

Lab safety warning: The first section deliberately creates a UID 0 account, which has root-level privileges, and modifies root's SSH authorized-keys file. These are persistence techniques commonly associated with unauthorized access. Run this only in a disposable, isolated virtual machine that you own. Do not run it on your everyday computer or a production system. The sample SSH line shown is not a complete valid public key, but the account creation still grants root-equivalent local access.

1. Enter Administrator Mode and Create the Lab Indicators

Enter a root shell:

sudo -i

In the isolated lab VM only, the following commands create an account with UID 0 and add a sample line to root's SSH authorized-keys file:

useradd -u 0 -o -g 0 -M -d /root -s /bin/bash support_linux_attack

mkdir -p /root/.ssh
echo "ssh-rsa attacker@evil" >> /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys

What these commands do:

  • useradd -u 0 -o creates a user with UID 0 and permits a duplicate UID. UID 0 is the root identity.
  • -g 0 assigns the account to the root group.
  • -M -d /root avoids creating a home directory and sets the home path to /root.
  • mkdir -p ensures the SSH directory exists.
  • authorized_keys is where SSH public keys permitted to log in are stored.
  • chmod 600 restricts the file so only its owner can read and write it.

2. Display Configured Linux User Accounts

Display the local account database:

cat /etc/passwd

Look for unfamiliar accounts and especially accounts with UID 0. More than one UID 0 account should be investigated.

3. Search Running Processes

Search the process list for common shell and network utility names:

ps aux | grep -E 'nc|bash|sh'

Review the full command, process owner, PID, and parent process. A match is not automatically malicious: shells and network tools are also used for legitimate administration.

4. Display Active Network Connections and Listening Ports

sudo ss -tulpn

This displays TCP and UDP sockets, listening ports, and (where permissions allow) the associated process information. Investigate unexpected listening services and unfamiliar remote connections.

5. Remove the Lab Account After Testing

The account created in Step 1 is named support_linux_attack. The original removal command used a different name (support_linux), so it would not remove the account created by the practical.

userdel -f support_linux_attack
Important notes
  • Do not use userdel -f as a routine cleanup method on a real system. Confirm the account name and investigate any associated processes or files first.
  • cat /etc/passwd lists account records, not passwords. Password hashes are generally stored in the protected /etc/shadow file.
  • The process search can return false positives, including the grep command itself. Verify each result before taking action.
  • For a real incident, preserve logs and evidence before deleting accounts or changing SSH files.
Practical outcome: The commands demonstrate how to inspect local accounts, investigate suspicious processes, review listening network services, and identify potentially unauthorized root and SSH access configuration.
