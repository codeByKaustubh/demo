Secure Password Storage with Hashing and Salt

Implementing password hashing and verification in Python using PBKDF2-HMAC-SHA256.

Aim

To demonstrate secure password storage using hashing and salt in Python.

Python Code: pass.py

Create a file named pass.py and paste the following program. It generates a random salt, derives a password hash using PBKDF2-HMAC-SHA256, and verifies a second password entry.

import hashlib, secrets, getpass

ITERATIONS = 600_000

def hash_password(password):
    salt = secrets.token_bytes(16)
    hashed = hashlib.pbkdf2_hmac("sha256", password.encode(), salt, ITERATIONS)
    return salt, hashed

print("=== Secure Password Storage ===")

password = getpass.getpass("Enter password: ")

salt, stored_hash = hash_password(password)

print("Password hashed successfully.")
print("Salt:", salt.hex())
print("Hash:", stored_hash.hex())

check = getpass.getpass("\\nEnter password to verify: ")

new_hash = hashlib.pbkdf2_hmac("sha256", check.encode(), salt, ITERATIONS)

if secrets.compare_digest(new_hash, stored_hash):
    print("Password is CORRECT")
else:
    print("Password is INCORRECT")

1. Create the Python File

Open the Ubuntu terminal and create the file:

nano pass.py

Paste the Python code above. Save using Ctrl + O, press Enter, and exit using Ctrl + X.

2. Run the Program

python3 pass.py

Enter a test password when prompted. The password will not appear on the screen while you type because the program uses getpass.

3. Verify the Password

When prompted with Enter password to verify:, enter the same password to see:

Password is CORRECT

Enter a different password to see:

Password is INCORRECT

4. Understand the Main Components

  • hashlib: Provides the PBKDF2-HMAC-SHA256 password-based key derivation function.
  • secrets.token_bytes(16): Generates a cryptographically secure random 16-byte salt.
  • PBKDF2: Repeats the hash operation for the configured 600,000 iterations to make password guessing more expensive.
  • Salt: A unique random value combined with the password before deriving the hash. It prevents identical passwords from automatically producing identical stored hashes.
  • secrets.compare_digest(): Compares the derived hash with the stored hash using a timing-resistant comparison.
Important security notes
  • This program is a learning demonstration. It stores the salt and hash only in memory and prints them; it does not save a persistent password record.
  • In a real application, store the salt, derived hash, algorithm name, and iteration count together so the password can be verified later.
  • Never store or log plaintext passwords. Use a dedicated password-hashing scheme such as Argon2id, scrypt, or PBKDF2 with current parameters and a unique random salt per password.
  • The 600,000 iteration count is the value specified in this practical; appropriate parameters should be reviewed periodically for the target system.
Practical outcome: The program demonstrates how a random salt and a deliberately slow password-based key derivation function can be used to create and verify a password hash without storing the plaintext password.
