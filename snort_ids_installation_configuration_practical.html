Snort IDS Installation and Configuration

Installing Snort on Ubuntu and monitoring network traffic for suspicious activity.

Aim

To install and configure the Snort Intrusion Detection System (IDS) and monitor network traffic for suspicious activity.

Before you begin: These instructions are written for the Snort 2.x package commonly provided by Ubuntu's apt repositories. Snort 3 uses different command-line options and configuration conventions. Check your version with snort -V and use the matching documentation if it reports Snort 3.

1. Enter Administrator Mode and Update Ubuntu

Open the Ubuntu terminal and enter:

sudo -i
apt update
apt upgrade -y

sudo -i opens a root shell. The original sudo -I uses an uppercase i and is incorrect; use lowercase -i.

2. Display Network Interfaces and IP Addresses

ip a

Identify the interface that receives the traffic you want Snort to monitor, such as ens33, enp0s3, or eth0. Record the Ubuntu IP address.

3. Install Snort IDS

apt install snort -y

During installation, the package may ask for the network interface or HOME_NET range. Enter the correct values for your lab network. The version command confirms which Snort generation was installed.

snort -v

5. Open the Snort Configuration File

In a new terminal, open the Snort 2 configuration file:

sudo nano /etc/snort/snort.conf

Review the configuration, especially the ipvar HOME_NET setting and the inclusion of local rules (commonly include $RULE_PATH/local.rules). Save changes only when needed.

6. Restart Snort and Check Its Service

sudo systemctl restart snort
sudo systemctl status snort

Some package configurations do not provide an enabled or running systemd service by default. If the service is missing or fails, inspect the error output and validate the installed configuration; you can run Snort manually as shown in Step 8.

7. Add Custom Rules to local.rules

Open the local rules file:

sudo nano /etc/snort/rules/local.rules

For a controlled lab, the following Snort 2 rules can alert on ICMP echo requests (such as ping), new TCP connection attempts to SSH port 22, and HTTP requests containing /etc/passwd in the URI:

alert icmp any any -> any any (msg:"ICMP Connection Attempt"; sid:1000010; rev:1;)
alert tcp any any -> any 22 (msg:"SSH connection attempt"; sid:100002; rev:1;)
alert tcp any any -> any 80 (msg:"Command Execution Attempt"; content:"GET"; content:"/etc/passwd";sid:100003; rev:1;)

Save the file. These are demonstration alerts, not proof that an attack succeeded. The SSH rule detects an initial TCP SYN to port 22; the HTTP rule detects a matching request only if it is visible to the monitored interface and uses unencrypted HTTP.

8. Run Snort with the Main Configuration and Show Alerts

Open a new terminal and run Snort 2 using the main configuration file. Do not pass local.rules to -c: that option expects the complete Snort configuration, not a rules file.

sudo snort -q -A console -c /etc/snort/rules/local.rules

9. Generate Test Traffic from the Host Computer

From the host computer, use its terminal or Command Prompt. Replace <ubuntu_ip> with the Ubuntu VM's IP address:

ping <ubuntu_ip>
ssh admin@<ubuntu_ip>
curl http://<ubuntu_ip>/etc/passwd
  • ping: Generates ICMP echo requests. The ICMP rule should alert if Snort sees the packets.
  • ssh: Attempts a connection to TCP port 22. SSH must be installed and listening for a connection to complete; the SYN packet can trigger the Snort rule.
  • curl: Sends an HTTP request for the path /etc/passwd. This does not directly read Ubuntu's local /etc/passwd file. An HTTP server must be running and configured to serve that path for content to be returned. The rule only alerts if the request is plain HTTP and visible to Snort.
Important troubleshooting notes
  • Snort must monitor the interface through which the host's traffic actually arrives. In a VM, check VMware network mode, routing, and interface selection.
  • Traffic sent to 127.0.0.1 stays on the same machine and will not normally appear on the VM's external network interface.
  • HTTPS encrypts the HTTP URI, so a basic network rule cannot inspect /etc/passwd inside encrypted HTTPS traffic.
  • If no alerts appear, verify that the local rules are included in snort.conf, the interface is correct, HOME_NET matches the Ubuntu network, and Snort is using the expected configuration.
  • Run these tests only on systems and networks you own or are authorized to assess.
Practical outcome: Snort is installed and configured to inspect selected network traffic and display alerts for the demonstration ICMP, SSH, and HTTP patterns.
